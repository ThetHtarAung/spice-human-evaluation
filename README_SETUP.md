# SPICE Human Evaluation — Final 18 Stories × 6 Models Setup

## Final study design

- Dataset: ViStoryBench-Lite
- Stories: 18
- Models: 6
- Model × story sequences: 108
- Raters per sequence: 3
- Total sequence evaluations: 324
- Participants: 54
- Sequences per participant: 6
- Assignment: exactly one sequence per model and six different stories per participant
- Alignment: 5 evenly spaced frames per story
- Per story: 5 alignment ratings + 6 full-sequence ratings = 11 ratings
- Per participant: 66 ratings

Models:
1. NaiveBaseline
2. StoryDiffusion_photomaker
3. UNO
4. NanoBanana
5. QwenImageEdit-2509
6. Gemini

Stories:
1, 8, 9, 15, 17, 24, 27, 28, 29, 32, 52, 53, 55, 57, 60, 64, 68, 79

---

## Files

- `index.html` — final participant-facing survey
- `Code.gs` — Google Apps Script backend for Google Sheets

## Step 1 — Put the ViStoryBench data in the folder structure

For each of the 18 stories:

- `prompts.json` goes in the shared story folder.
- reference-character images go in `refs/`.
- each model's generated story frames go in that model's `frames/` folder.

Do not duplicate `prompts.json` and references for every model.

---

## Step 2 — Generate and validate `manifest.json`

From the project root:

```bash
python generate_manifest.py
```

The script checks:

- all 18 stories exist;
- all 6 models exist for each story;
- all 108 model × story combinations are present;
- every sequence contains the expected number of generated frames.

If anything is missing, it refuses to write the final manifest and tells you which folder is incomplete.

## Step 3 — Participant assignments

A final balanced `data/assignments.json` is already included.

The design contains:

- G01–G54;
- 6 sequences per group;
- each model exactly once per participant;
- no repeated story within a participant;
- every model × story cell exactly 3 times;
- randomized presentation order.

If you want to regenerate it:

```bash
python generate_assignments.py
```

The random seed is fixed to `20260827` for reproducibility.

## Step 4 — Create the online Google Sheet

Create one blank Google Sheet.

Copy its spreadsheet ID from a URL of the form:

```text
https://docs.google.com/spreadsheets/d/SPREADSHEET_ID/edit
```

Open:

**Extensions → Apps Script**

Paste the complete contents of `Code.gs`.

Replace:

```javascript
const SPREADSHEET_ID = "PASTE_GOOGLE_SHEET_ID_HERE";
```

with your actual spreadsheet ID.

Run:

```javascript
setupSheets()
```

once from the Apps Script editor and grant permission.

It creates three sheets:

### `SequenceRatings`

One row per participant × story-model sequence.

Expected final main-study size:

```text
324 rows
```

It contains the seven human scores plus participant and item metadata.

### `AlignmentRatings`

One row per sampled alignment frame.

Expected size if everyone completes all five:

```text
324 × 5 = 1,620 rows
```

### `ParticipantSessions`

One row per completed participant.

Expected final size:

```text
54 rows
```

## Step 5 — Deploy the Apps Script

In Apps Script:

1. Click **Deploy**
2. **New deployment**
3. Select **Web app**
4. Execute as: **Me**
5. Who has access: **Anyone**
6. Deploy
7. Copy the URL ending in `/exec`

In `index.html`, replace:

```javascript
googleAppsScriptUrl:"PASTE_YOUR_GOOGLE_APPS_SCRIPT_WEB_APP_URL_HERE",
```

with the `/exec` URL.

For the real study keep:

```javascript
requireOnlineSubmission:true
```

For temporary local/interface testing you can use:

```javascript
requireOnlineSubmission:false
```

Every submission is also kept as a local browser backup.

## Online spreadsheet vs Excel Online

For this static GitHub survey, Google Sheets + Apps Script is recommended for live data collection.

Why:
- simple anonymous POST endpoint;
- no participant sign-in;
- no OAuth token in the browser;
- easy to inspect during pilot collection;
- easy to export later as `.xlsx` or `.csv`.

After data collection, download the Google Sheet as Excel if you want to do analysis in Excel, Python, R, SPSS, etc.

---

## Important data-analysis note

The primary analysis unit is the **108 model × story sequences**, not the six model averages.

For each sequence:
1. average its three human raters;
2. calculate inter-rater reliability;
3. compare the corresponding human dimension with the matching SPICE component.

Also retain `num_frames` so story-length effects can be tested.
